# 消息写入压测

`k6-send.js` 使用开放模型产生固定到达率，避免服务变慢时负载生成器也同步降速。默认先执行 10 分钟常态 3,000 条/秒，再执行 15 分钟峰值 9,000 条/秒。

准备一组已经存在且成员关系有效的会话身份，尽量覆盖四个分片和所有表组：

```bash
export IM_IDENTITIES='[
  {"conversationId":"018f0000-0000-7000-8000-000000000001","userId":"018f0000-0000-7000-8000-000000000002"}
]'
k6 run load/k6-send.js
```

正式验收需要从独立压测机运行，入口指向负载均衡器，并启用与生产一致的 TLS、MySQL 高可用和 RocketMQ 副本配置。执行期间同时记录应用延迟、连接池等待、MySQL redo/binlog、行锁时间、RocketMQ 发送延迟、Outbox 最老未发布时间和丢弃迭代数。

此脚本只覆盖发送写入容量。连接爬坡、18 万次/秒设备投递、重连风暴、幂等竞争、故障和 24 小时长稳应使用独立场景，避免不同瓶颈互相掩盖。
